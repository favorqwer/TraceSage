# Provenance-Navigator: 神经符号混合双向因果拓扑与离线知识蒸馏导航系统

---

## 第一部分：目标方案的详细描述 (Target Architecture & Innovation Blueprint)

### 1.1 系统定位与现有技术瓶颈剖析

**Provenance-Navigator（因果溯源导航系统）** 是面向企业级多主机系统调用日志（Sysdig/SCAP/ETW）与企业级溯源图（Neo4j）的高性能攻击路径溯源调查与智能导引系统。

在基于系统调用的主机级威胁溯源图调查领域，现有技术长期受困于两大传统技术范式的不可调和矛盾：

1. **传统规则与纯图遍历引擎的泛化困境**：
   传统专家规则严重依赖具体实体的字面量（如硬编码特定的脚本文件名称、特定进程名、固定网络地址或端口）。一旦攻击者采用多态载荷、利用无文件内存执行、或切换至新攻击场景，硬编码规则迅速大面积失效；同时，传统规则缺乏全局因果感知能力，容易对系统日常的复杂运维操作产生级联误报。
2. **纯大语言模型（LLM）与黑盒图深度学习的资源与可靠性困境**：
   若完全依赖大语言模型对全图的每一跳系统调用进行单步推理，调查过程不仅面临极高的网络延迟、昂贵的 Token 计算开销和判定非确定性（幻觉），更致命的是操作系统每秒产生数以万计的正常事件（如读取公共系统库、查询硬件信息），导致溯源图产生**依赖爆炸与上下文窗口溢出**，大语言模型极易在海量无关背景边中迷航。

**本方案的核心理论突破与创新思路**：
提出**“基于攻防全状态先验对抗闭环的神经符号双通道路由与导航调查体系”**。通过构建自动化对抗演进数据闭环，利用数据驱动的弱监督统计学习方法，将攻击知识提炼为**去字面化的抽象图拓扑因果基模**；在在线端到端调查中，彻底解耦**高确定性攻击拓扑（由快速符号规则接管，实现零模型开销与毫秒级极速响应）**与**高歧义深层意图（由慢速大语言模型接管，实现精准破局）**，从根本上解决溯源图调查中的效率、泛化性与依赖爆炸三大核心矛盾。

### 1.2 创新维度一：基于攻击全状态先验的高保真因果对抗数据底座

任何数据驱动的知识蒸馏体系，其性能上限均取决于训练样本的真实度与标准答案的纯度。针对网络安全领域真实攻击数据集极度匮乏、标注口径混乱且主观偏差严重的行业痛点，本系统采用了一套全状态先验的对抗数据底座：

1. **真实攻击编排与单机采集（该环节在本仓库之外，过程记录见 `attack/AGENTS.md`）**：
   攻击侧由编排代理经 SSH 在实验网内的四台虚拟机上驱动**真实攻击**（真实公开漏洞、真实攻击框架、真实加密与真实传输，明确禁止“打印几行字假装偷数据”），覆盖侦察探测、初始访问、特权提升、横向移动、持久化维持与数据外发等阶段；受害机由人工在本地控制台上启停 Sysdig 录制，探针完整捕获高并发系统背景噪声下的微观系统调用序列。
   **边界声明**：编排与采集的代码不在本仓库，仓库内落地的是它们的产物（`attack/data/<场景>/capture.scap`）；采集只覆盖受害者一台机器、不含 `host_id`，跨主机关联不在当前范围内。
2. **基于攻击全状态先验的无歧义人工精准标注**：
   在传统的应急取证中，安全分析人员面对海量日志往往只能事后猜测攻击意图，导致漏标与错标。而在本体系中具备**全知先验条件**：标注者完全掌握攻击方在每一个时间戳下发起的具体执行逻辑、涉及的进程标识符、创建的文件对象与目标网络连接。
   标注者据此对照底层系统调用日志进行精确对齐与因果回溯，标注出没有主观猜测成分、因果闭环的**真实攻击路径标准答案（Ground Truth）**；标准答案里的每一条可能集合规则还要求在场景图上实测验证（纯度／互斥／两不相交三条硬约束），实测条数与验证结论如实写进标准答案文件。
3. **演进机制现状（诚实边界）**：
   新增一个场景需要人工重新完成“编排攻击 → 采集 → 标注 → 在图上验证规则”四步，**目前不是自动闭环**。仓库现有 5 个已标注场景（`attack/data/1..5`），另有 `attack/data/6`、`7`、`9`、`10` 四个场景只有采集产物、尚无标准答案，因此既不参与蒸馏也不参与评测。

### 1.3 创新维度二：全自动频繁子图挖掘与全背景对抗剪枝的离线知识蒸馏算法

为将上述高保真对抗数据转化为具备跨场景泛化能力的确定性检测规则，系统设计了**基于频繁子图挖掘与纯对抗信噪比筛选的因果拓扑蒸馏算法**，在本模块内不再使用手工字典与预选基模列表：

1. **实体与关系的语义角色客观拓扑抽象（本模块内无字典依赖）**：
   系统在解析训练集中的真实攻击边时，严格执行基于 Sysdig 系统调用因果流向与 POSIX/FHS 标准领域常识的去字面化抽象。该抽象不含任何“恶意工具名／良性工具名”判定表，纯基于客观拓扑属性判定（系统其它环节残留的固定字面量知识见 2.1 节声明边界）：
   - **客体角色抽象**：将节点映射为“网络套接字端点（Socket）”、“标准持久化配置（`/etc/systemd`, `/etc/cron`）”、“系统敏感认证凭据（`/etc/shadow`, `authorized_keys`）”、“非标准目录下的落地载荷客体（由活跃进程写入且排除系统公共动态库）”；
   - **主体角色抽象**：根据主体在因果图上的动作，抽象为“入站服务端进程”、“外联网络工具进程”、“特权属性修改进程”、“解释器与派生父进程”、“探测叶子进程”等。
2. **频繁因果子图拓扑骨架（Motifs）的全自动挖掘**：
   系统通过 `FrequentSubgraphMiner` 模块，从多场景的 Ground Truth 有向多重图中自动抽取高频因果拓扑：
   - **1-跳核心原子拓扑**：`(src_role, syscall, dst_role)`，如 `(INBOUND_SERVER_PROC, execve, INTERPRETER_OR_SPAWNER_PROC)`、`(OUTBOUND_NET_PROC, write, DROPPED_OBJECT)`；
   - **2-跳连续因果链骨架**：`(src_role, sc1, mid_role, sc2, dst_role)`，如入站会话派生载荷、落地载荷赋权并派生执行等跨场景高频链条；
   - **挖掘支持度解耦**：挖掘阶段默认门限为 `min_support=1`，彻底消除与训练数据集规模（如 $N=4$）的人为强行绑定，确保单一场景但攻击模式高度典型的罕见关键因果链不被误杀。
3. **三值标签与全背景对抗提升度准入机制**：
   蒸馏器 `OfflineDistiller` 把训练场景候选池里的每条边唯一地归入三类身份，避免把“已知是攻击但边界划不清”的边当作正样本或负样本：
   - **正样本**：命中标准答案必须条目的边——唯一无歧义的攻击标签，保证先验概率停留在真实的稀有量级；
   - **忽略集**：未命中必须条目、但符合标准答案人工规则的边（如加密、打包这类条数随环境变化的步骤）——既不记命中也不记误报，整体剔除出统计；
   - **负样本**：其余候选边。
   准入判据为贝叶斯经验提升度检验：先验概率 $\pi = \text{池内正样本数} / (\text{池内正样本数} + \text{池内负样本数})$（分子分母同源，忽略集不参与），后验平滑精度 $P_{Bayes} = (TP + m_0\pi)/(TP + FP + m_0)$（默认 $m_0=2.0$），要求 $Lift = P_{Bayes}/\pi \ge 3.0$ 且 $TP \ge 1$。审计流水如实记录池内正/忽略/负三个分量，保证判据可独立复算。
   - **在线第二道门槛（候选资格不等于确认）**：离线入选只给基模候选资格；在线匹配时，命中基模的边还要求该基模在训练池上的命中查准率 $\ge$ `matcher_min_conf`（当前 `0.50`，精度优先取值）才把边确认；未达标者退入报告「未排除」段而不丢失。生效取值与被否决次数如实写入报告 `stats.matcher_min_conf` 与 `stats.conf_filtered_count`。该门槛是规则模式召回／查准取舍的直接来源：收紧则查准升、召回降，放宽反之（当前基线两侧取值下的实测差异见基准记录文件）。
   - 已知局限：忽略集被剔除后，命中正样本极少但命中大量忽略边的基模会缺少证伪证据，最小证据量约束属独立改动，当前版本未引入。
4. **操作系统通用进程血缘树传递与会话级活跃网络桥接**：
   - **进程血缘树递归继承（Process Lineage Tree）**：由确诊攻击进程或会话解释器通过 `execve` / `clone` 派生的所有子命令进程全链条自动继承确诊状态（$PPID \in high\_conf\_pids \implies PID \in high\_conf\_pids$），无需维护任何侦察命令字典；
   - **会话级活跃网络桥接（SessionActiveBridge）**：针对 `sshd`、`nginx` 等共享多租户守护进程，仅桥接具体派生了确诊攻击子进程的有效五元组会话端点，杜绝盲目按 IP 桥接导致的端口扫描误报扩散。

### 1.4 创新维度三：高内聚低耦合的四模块架构与三工作模式

系统全面重构为**高内聚、低耦合**的四大独立子模块：

```
                    [目标异常事件 (POI: File/Network)]
                                   │
                                   ▼
        ┌──────────────────────────────────────────────────┐
        │ 1. closure (因果闭包抽取与事实抽象)              │
        │ - 直连底层 Neo4j 图数据库自主反向展开因果图谱    │
        │ - 构建入度/出度拓扑事实索引 (TopologyFacts)      │
        └─────────────────────────┬────────────────────────┘
                                   │
                                   ▼
        ┌──────────────────────────────────────────────────┐
        │ 4. orchestrator (协同编排与调查报告)             │
        │                                                  │
        │ ┌──────────────────────────────────────────────┐ │
        │ │ 通道一：静态只读因果初筛 (filter.py)         │ │
        │ │ -> 毫秒级剥离无前序污染且无交付的静态只读库  │ │
        │ └──────────────────────────────────────────────┘ │
        │                         │                        │
        │                         ▼                        │
        │ ┌──────────────────────────────────────────────┐ │
        │ │ 通道二：离线抽象基模匹配 (2. rules 模块)     │ │
        │ │ -> matcher.py 匹配离线 distiller.py 规则     │ │
        │ │ -> 0 模型调用毫秒级直接确认攻击主干链路      │ │
        │ └──────────────────────────────────────────────┘ │
        │                         │ (未命中歧义边)         │
        │                         ▼                        │
        │ ┌──────────────────────────────────────────────┐ │
        │ │ 通道三：拓扑歧义度慢速通道 (3. judge 模块)   │ │
        │ │ -> bridge.py 组装因果子图上下文              │ │
        │ │ -> client.py 调用大模型进行深层语义仲裁      │ │
        │ └──────────────────────────────────────────────┘ │
        │                                                  │
        │ ┌──────────────────────────────────────────────┐ │
        │ │ 报告持久化与审计 (report.py)                 │ │
        │ │ -> 输出 edges / unexcluded / excluded 三段   │ │
        │ └──────────────────────────────────────────────┘ │
        └──────────────────────────────────────────────────┘
```

#### 系统原生支持的三大工作模式

1. **`rules`（纯规则模式）**：
   - **适用场景**：离线物理隔离网络、极低延迟要求、资源受限计算节点；
   - **行为特征**：初筛静态只读库后，仅由抽象基模判定攻击边，**LLM 调用量恒为 0 次**，耗时在秒级内完成；未命中规则的非初筛边安全留存于 `unexcluded` 待查池中。
2. **`hybrid`（智能路由模式）**：
   - **适用场景**：默认生产推荐模式，兼顾极致吞吐率、高查准率与高召回率；
   - **行为特征**：神经符号双通道协同，符号规则优先毫秒级锁定高确信度链路（0 开销），仅将残余的高歧义候选边交由 LLM 进行深层语义裁决。
3. **`llm-only`（纯 LLM 模式）**：
   - **适用场景**：遭遇罕见未知攻击手法的零日利用场景、或对抗离线规则特征的新型渗透链；
   - **行为特征**：初筛剥离海量静态无害库后，跳过离线规则直连慢速通道，全量歧义边由 LLM 结合上下文进行全维因果仲裁。

### 1.5 创新点提炼总结（创新贡献清单）

- **创新点一：基于攻击全状态先验的高保真因果对抗数据底座**
  攻克了网络安全图调查领域标准答案标注主观性强、易漏标错标的行业痛点。在完全掌握攻击方全状态的前置先验下，构建了对齐到事件级、且规则约束经过图上实测验证的人工因果标准答案，为后续知识蒸馏建立了可信赖的数据基础。**边界**：场景编排与采集环节在本仓库之外（记录见 `attack/AGENTS.md`），所谓“自动演进的数据飞轮”未实现，新增场景仍需人工参与。
- **创新点二：去字面化的抽象图因果拓扑基模离线蒸馏方法**
  攻克了传统规则强依赖字面量导致泛化性差、以及大语言模型计算开销巨大的双重困境。提出了面向图因果关系的语义角色抽象与弱监督对抗修剪算法，实现了从对抗日志中全自动挖掘跨场景通用、抗背景噪声的抽象图拓扑因果基模。**边界**：去字面化覆盖的是“角色抽象 + 基模挖掘 + 统计准入”这一段；系统其它环节仍含少量固定字面量知识，完整清单与用途见 2.1 节。
- **创新点三：解耦拓扑确定性与深层语义的神经符号双通道导航架构**
  攻克了图溯源调查中静态库依赖爆炸与上下文过载难题。创立了由因果初筛和蒸馏规则构成的毫秒级快速符号通道，协同基于因果上下文增强的大语言模型慢速语义通道，实现了在大模型调用量极低乃至为零的极限约束下，兼顾高吞吐率与高查准率的端到端自主调查。**边界**：泛化能力目前只在同一实验环境的 5 个场景上按跨场景留一协议验证过，跨发行版、跨环境尚未测量（残留字面量清单与已知泛化风险点见 2.1 节）。

## 第二部分：代码实现与边界声明 (Code Architecture & Boundaries)

遵循项目工程规范中的**声明边界法则**与**独立可验证法则**，在此明确当前代码的真实落地深度与客观边界。

### 2.1 声明边界：输入来源与当前运行范围

- **数据源现状**：
  - 目前代码库用于离线蒸馏与测试验证的数据源，为本地归档的 5 个基准网络威胁场景日志（覆盖 Web 漏洞利用勒索、SSH 暴力破解横向移动、钓鱼邮件挖矿木马、代码仓库投毒后门、暴露服务横向枢纽）以及对应的人工标注标准答案；
  - **场景的产生环节不在本仓库**：攻击由编排代理经 SSH 在实验网内驱动真实攻击、受害机由人工启停 Sysdig 录制，过程记录见 `attack/AGENTS.md`；本仓库只落采集产物（`capture.scap`）与标注；
  - **单机边界**：采集只覆盖受害者一台机器、不含 `host_id`，跨主机横向移动关联不在当前数据范围内；
  - `attack/data/6`、`7`、`9`、`10` 四个场景只有采集产物、没有标准答案，不参与蒸馏与评测；
  - 系统直连本地 Neo4j 图数据库，全自主展开反向因果闭包。
- **调查起点（目标异常事件）**：
  - 场景清单与调查起点（POI 事件）的唯一真源为 `provenance-agent/config/scenarios.json`（人工指定，属外部前置输入）；导航器直连底层 Neo4j 图数据库，自锚点起全自主展开反向因果闭包。
- **残留字面量知识（诚实清单）**：基模的节点角色抽象、频繁子图挖掘与统计准入三段不含任何工具名判定，但下列环节仍依赖固定的字面量常量，是跨发行版、跨平台泛化的已知风险点：

| 位置 | 字面量 | 用途 | 性质 |
|---|---|---|---|
| `closure/facts.py:94` | 12 项可执行名（`sh` `bash` `dash` `zsh` `python` `python3` `perl` `php` `tar` `curl` `wget` `socat`） | 入站会话派生进程的污染传播：命中即把父子进程标记为受污染 | 可执行名列表，不区分攻防用途，但含 `curl`／`wget`／`socat` 等攻防两用名 |

### 2.5 边界穿越故事通道（Boundary-Story Channel，默认关闭）

与 `rules/matcher.py`（基模匹配与手写闭环）、`orchestrator/bridge.py`（会话桥接与诱导闭环）
**并列的第三条符号促进通路**，同属「通道二」的促进环节，**只增不减**：它只把候选边提升为已确认，
不删除任何既有确认边（实测五折「剔除 = 0」）。**默认开启**，在 `rules` 与 `hybrid` 两个模式下运行（`llm-only` 按设计跳过全部符号通道）。

**判据（六步，全部与标准答案无关）**

1. **宽入口（观测边界穿越）**：同一个连接对象上同时出现 `connect` 与 `accept` ⇒ 两端都在本机、都被观测到；
   只出现其一 ⇒ 另一端在观测窗口之外，是候选入口（不假设入站或出站，也不用 IP 名单）。
2. **现学对手指纹**：从「锚点边 + 高精度家族边（`MINED_*`、`REFINED_ACTIVE_BRIDGE`）+ 涉及窗口内新造对象的确认边」
   里提取对端 IP；指纹是数据内现学的，不是外挂名单。
3. **攻击主体与攻击产物**：与带指纹对端的连接打过交道的进程 = 攻击主体；它们写出的非伪文件对象 = 攻击产物。
4. **严格成因**：只确认「走在带指纹对端的连接上 / 攻击产物被写出-读取-执行 / 跨**程序**（非跨进程号）的管道交接 /
   攻击主体读取窗口内新造的非伪文件对象」四类之一。
5. **伪文件排除**：内核按需生成、不承载内容的伪对象（`/sys`、`/proc`、`/dev` 下设备与终端节点、`memfd:`、匿名 IPC）
   不计为攻击产物；`/dev/shm`、`/run/shm`、`/tmp` 等可写内存/临时文件系统**故意保留**（真实载荷常落地于此）。
6. **链条继续**：沿「消费攻击产物 / 被攻击主体派生」迭代扩散，以覆盖非入站型入口（如钓鱼投递）。

**为什么可信**：① 判据只引用图内事实与操作系统本体事实，不引用标准答案（该模块内无任何读取标注的代码）；
② 只做加法，实测五折「剔除 = 0」，增益不可能来自「把东西移出评分集合」；③ 无阈值、无名单、无时间窗，
唯一人工输入是调查锚点（已声明为外部前置输入）。

**实测（真五折端到端、官方工具、完整确认集口径，`--mode rules`，本通道已默认开启）**

| 配置 | 召回（步骤） | 查准（边） | F1 | 大模型调用 | 五折耗时 |
|---|---|---|---|---|---|
| 未启用本通道（历史对照） | 81.1%（352/434） | 82.5%（9815/11904） | 0.8177 | 0 | 289.4s |
| **`rules`（本通道默认开启，现行基线）** | **91.5%（397/434）** | 81.5%（9861/12104） | **0.8619** | 0 | 285.9s |

逐场景：1=62/80（9072/9335）、2=49/52（432/809）、3=93/99（164/695）、4=57/64（57/629）、5=136/139（136/636）。
新增边归因：指纹对端套接字边 107、攻击产物写出 68、产物读取 11、产物执行 10、跨程序管道交接 2、主体读新造对象 2。

**已知边界（必须随数字一起声明）**

- **内存型入口（mmap/memfd/ptrace 无文件落地）观测不到**，本通道不覆盖；
- 窗口开始前已落地的载荷，「谁写的」在窗口外，链条在此断开；
- 「对端不可归因」只说明对方不在本机图里，不说明对方恶意；恶意与否由锚点与高精度家族的指纹限定，
  因此本通道必须依赖调查锚点（外部前置输入），不是端到端自主发现；
- 本通道是并列新增、**未替换**任何既有规则；离线投影与端到端在场景 3 相差 4 条边 / 1 个步骤，已在验收中如实记录。
