# Provenance-Navigator: 神经符号混合双向因果拓扑与离线知识蒸馏导航系统

---

## 第一部分：目标方案的详细描述 (Target Architecture & Innovation Blueprint)

### 1.1 系统定位与现有技术瓶颈剖析

**Provenance-Navigator（因果溯源导航系统）** 是面向企业级多主机系统调用日志（Sysdig/SCAP/ETW）与企业级溯源图（Neo4j）的高性能攻击路径溯源调查与智能导引系统。

在基于系统调用的主机级威胁溯源图调查领域，现有技术长期受困于两大传统技术范式的不可调和矛盾：

1. **传统规则与纯图遍历引擎的泛化困境**：
   传统专家规则严重依赖具体实体的字面量（如硬编码特定的脚本文件名称、特定进程名、固定网络地址或端口）。一旦攻击者采用多态载荷、利用无文件内存执行、或切换至新攻击场景，硬编码规则迅速大面积失效；同时，传统规则缺乏全局因果感知能力，容易对系统日常的复杂运维操作产生级联误报。
2. **纯大语言模型（LLM）与黑盒图深度学习的资源与可靠性困境**：
   若完全依赖大语言模型对全图的每一跳系统调用进行单步推理，调查过程不仅面临极高的网络延迟、昂贵的 Token 计算开销和判定非确定性（幻觉），更致命的是操作系统每秒产生数以万计的正常事件（如读取公共系统库、查询硬件信息），导致溯源图产生**依赖爆炸与上下文窗口溢出**，大语言模型极易在海量无关背景边中迷航。

**本方案的核心理论突破与创新思路**：
提出**“基于攻防全状态先验对抗闭环的神经符号双通道路由与导航调查体系”**。通过构建自动化对抗演进数据闭环，利用数据驱动的弱监督统计学习方法，将攻击知识提炼为**去字面化的抽象图拓扑因果基模**；在在线端到端调查中，彻底解耦**高确定性攻击拓扑（由快速符号规则接管，实现零模型开销与毫秒级极速响应）**与**高歧义深层意图（由慢速大语言模型接管，实现精准破局）**，从根本上解决溯源图调查中的效率、泛化性与依赖爆炸三大核心矛盾。

### 1.2 创新维度一：基于攻击全状态先验的高保真因果对抗数据飞轮

任何数据驱动的知识蒸馏体系，其性能上限均取决于训练样本的真实度与标准答案的纯度。针对网络安全领域真实攻击数据集极度匮乏、标注口径混乱且主观偏差严重的行业痛点，本系统设计了一套全状态先验对抗数据飞轮：

1. **自动化攻击智能体的连续多阶段渗透**：
   系统上游部署能够自主规划并执行全攻击链条的网络攻击智能体，覆盖侦察探测、初始访问漏洞利用、特权提升、横向移动、持久化维持与数据外发等阶段。攻击智能体在逼真的操作系统沙箱中运行，底层的 Sysdig 监控探针完整捕获高并发系统背景噪声下的微观系统调用序列。
2. **基于攻击全状态先验的无歧义人工精准标注**：
   在传统的应急取证中，安全分析人员面对海量日志往往只能事后猜测攻击意图，导致漏标与错标。而在本体系中具备**全知先验条件**：安全专家完全掌握攻击智能体在每一个时间戳下发起的具体执行逻辑、注入的进程标识符、创建的文件对象与目标网络连接。
   分析人员基于这份完整的攻击状态清单，对照底层系统调用日志进行精确对齐与因果回溯，人工标注出完全没有主观猜测成分、因果闭环且具备绝对权威性的**真实攻击路径标准答案（Ground Truth）**。
3. **数据飞轮的自适应演进机制**：
   攻击智能体每演进或拓展一种新型渗透技术，系统即可快速沉淀出对应的新攻击场景日志与高精度标准答案，为下游离线蒸馏模块提供源源不断、持续演进的高纯度对抗数据燃料。

### 1.3 创新维度二：全自动频繁子图挖掘与全背景对抗剪枝的离线知识蒸馏算法

为将上述高保真对抗数据转化为具备跨场景泛化能力的确定性检测规则，系统设计了**基于频繁子图挖掘与纯对抗信噪比筛选的因果拓扑蒸馏算法**，彻底淘汰手工字典与预选先验：

1. **实体与关系的语义角色客观拓扑抽象（彻底消除过拟合与字典依赖）**：
   系统在解析训练集中的真实攻击边时，严格执行基于 Sysdig 系统调用因果流向与 POSIX/FHS 标准领域常识的去字面化抽象。系统绝无任何黑客工具名白名单（如 `socat`、`curl`、`whoami`、`id` 等），纯基于客观拓扑属性判定：
   - **客体角色抽象**：将节点映射为“网络套接字端点（Socket）”、“标准持久化配置（`/etc/systemd`, `/etc/cron`）”、“系统敏感认证凭据（`/etc/shadow`, `authorized_keys`）”、“非标准目录下的落地载荷客体（由活跃进程写入且排除系统公共动态库）”；
   - **主体角色抽象**：根据主体在因果图上的动作，抽象为“入站服务端进程”、“外联网络工具进程”、“特权属性修改进程”、“解释器与派生父进程”、“探测叶子进程”等。
2. **频繁因果子图拓扑骨架（Motifs）的全自动挖掘**：
   系统通过 `FrequentSubgraphMiner` 模块，从多场景的 Ground Truth 有向多重图中自动抽取高频因果拓扑：
   - **1-跳核心原子拓扑**：`(src_role, syscall, dst_role)`，如 `(INBOUND_SERVER_PROC, execve, INTERPRETER_OR_SPAWNER_PROC)`、`(OUTBOUND_NET_PROC, write, DROPPED_OBJECT)`；
   - **2-跳连续因果链骨架**：`(src_role, sc1, mid_role, sc2, dst_role)`，如入站会话派生载荷、落地载荷赋权并派生执行等跨场景高频链条；
   - **挖掘支持度解耦**：挖掘阶段默认门限为 `min_support=1`，彻底消除与训练数据集规模（如 $N=4$）的人为强行绑定，确保单一场景但攻击模式高度典型的罕见关键因果链不被误杀。
3. **基于全量背景对抗的纯信噪比（Adversarial SNR）准入机制**：
   为防止基模在真实系统中引发误报，蒸馏器 `OfflineDistiller` 将挖掘出的候选基模置于全量训练场景的真实候选闭包（包含数万条系统日常良性噪声边）中进行全背景对抗压力测试：
   - **特权敏感配置模式**：涉及系统敏感认证与开机持久化修改的基模，要求全背景对抗查准率 $\ge 50\%$ 且误报 $\le 5$；
   - **通用系统因果模式**：要求全背景对抗查准率 $\ge 30\%$ 且误报 $< 300$；
   - 彻底废除 `Support < 2` 硬编码，纯以真实信噪比衡量模式的稳健性。
4. **操作系统通用进程血缘树传递与会话级活跃网络桥接**：
   - **进程血缘树递归继承（Process Lineage Tree）**：由确诊攻击进程或会话解释器通过 `execve` / `clone` 派生的所有子命令进程全链条自动继承确诊状态（$PPID \in high\_conf\_pids \implies PID \in high\_conf\_pids$），无需维护任何侦察命令字典；
   - **会话级活跃网络桥接（SessionActiveBridge）**：针对 `sshd`、`nginx` 等共享多租户守护进程，仅桥接具体派生了确诊攻击子进程的有效五元组会话端点，杜绝盲目按 IP 桥接导致的端口扫描误报扩散。

### 1.4 创新维度三：高内聚低耦合的四模块架构与三工作模式

系统全面重构为**高内聚、低耦合**的四大独立子模块：

```
                    [目标异常事件 (POI: File/Network)]
                                   │
                                   ▼
        ┌──────────────────────────────────────────────────┐
        │ 1. closure (因果闭包抽取与事实抽象)              │
        │ - 直连底层 Neo4j 图数据库自主反向展开因果图谱    │
        │ - 构建入度/出度拓扑事实索引 (TopologyFacts)      │
        └─────────────────────────┬────────────────────────┘
                                   │
                                   ▼
        ┌──────────────────────────────────────────────────┐
        │ 4. orchestrator (协同编排与调查报告)             │
        │                                                  │
        │ ┌──────────────────────────────────────────────┐ │
        │ │ 通道一：静态只读因果初筛 (filter.py)         │ │
        │ │ -> 毫秒级剥离无前序污染且无交付的静态只读库  │ │
        │ └──────────────────────────────────────────────┘ │
        │                         │                        │
        │                         ▼                        │
        │ ┌──────────────────────────────────────────────┐ │
        │ │ 通道二：离线抽象基模匹配 (2. rules 模块)     │ │
        │ │ -> matcher.py 匹配离线 distiller.py 规则     │ │
        │ │ -> 0 模型调用毫秒级直接确认攻击主干链路      │ │
        │ └──────────────────────────────────────────────┘ │
        │                         │ (未命中歧义边)         │
        │                         ▼                        │
        │ ┌──────────────────────────────────────────────┐ │
        │ │ 通道三：拓扑歧义度慢速通道 (3. judge 模块)   │ │
        │ │ -> bridge.py 组装因果子图上下文              │ │
        │ │ -> client.py 调用大模型进行深层语义仲裁      │ │
        │ └──────────────────────────────────────────────┘ │
        │                                                  │
        │ ┌──────────────────────────────────────────────┐ │
        │ │ 报告持久化与审计 (report.py)                 │ │
        │ │ -> 输出 edges / unexcluded / excluded 三段   │ │
        │ └──────────────────────────────────────────────┘ │
        └──────────────────────────────────────────────────┘
```

#### 系统原生支持的三大工作模式

1. **`rules`（纯规则模式）**：
   - **适用场景**：离线物理隔离网络、极低延迟要求、资源受限计算节点；
   - **行为特征**：初筛静态只读库后，仅由抽象基模判定攻击边，**LLM 调用量恒为 0 次**，耗时在秒级内完成；未命中规则的非初筛边安全留存于 `unexcluded` 待查池中。
2. **`hybrid`（智能路由模式）**：
   - **适用场景**：默认生产推荐模式，兼顾极致吞吐率、高查准率与高召回率；
   - **行为特征**：神经符号双通道协同，符号规则优先毫秒级锁定高确信度链路（0 开销），仅将残余的高歧义候选边交由 LLM 进行深层语义裁决。
3. **`llm-only`（纯 LLM 模式）**：
   - **适用场景**：遭遇罕见未知攻击手法的零日利用场景、或对抗离线规则特征的新型渗透链；
   - **行为特征**：初筛剥离海量静态无害库后，跳过离线规则直连慢速通道，全量歧义边由 LLM 结合上下文进行全维因果仲裁。

### 1.5 创新点提炼总结（创新贡献清单）

- **创新点一：基于攻击全状态先验的高保真因果对抗数据飞轮**
  攻克了网络安全图调查领域标准答案标注主观性强、易漏标错标的行业痛点。依托自动化网络攻击智能体持续生成底层日志，并在完全掌握智能体攻击全状态的前置先验下，构建了机器级精度的人工因果标准答案，为后续知识蒸馏建立了可信赖的数据基础。
- **创新点二：去字面化的抽象图因果拓扑基模离线蒸馏方法**
  攻克了传统规则强依赖字面量导致泛化性差、以及大语言模型计算开销巨大的双重困境。提出了面向图因果关系的语义角色抽象与弱监督对抗修剪算法，实现了从海量对抗日志中全自动挖掘跨场景通用、抗背景噪声的抽象图拓扑因果基模。
- **创新点三：解耦拓扑确定性与深层语义的神经符号双通道导航架构**
  攻克了图溯源调查中静态库依赖爆炸与上下文过载难题。创立了由因果初筛和蒸馏规则构成的毫秒级快速符号通道，协同基于因果上下文增强的大语言模型慢速语义通道，实现了在大模型调用量极低乃至为零的极限约束下，兼顾高吞吐率、高查准率与强泛化性的端到端自主调查。

### 2.4 快速上手与操作指南

所有操作均在项目根目录虚拟环境中执行：

#### 1. 运行单场景自主调查（直连 Neo4j，端到端执行）
```bash
# 1. 纯规则离线模式（0 LLM 开销，毫秒级响应）
.venv/Scripts/python.exe provenance-navigator/main.py --scenario 1_Web_Exploit_Ransomware --mode rules

# 2. 神经符号智能混合模式（推荐默认生产模式）
.venv/Scripts/python.exe provenance-navigator/main.py --scenario 1_Web_Exploit_Ransomware --mode hybrid

# 3. 纯 LLM 深度模式（罕见未知攻击场景）
.venv/Scripts/python.exe provenance-navigator/main.py --scenario 1_Web_Exploit_Ransomware --mode llm-only

# 运行官方评分工具进行打分
.venv/Scripts/python.exe tools/eval_agent_attack_path.py \
  --report output/agent-runs/1_Web_Exploit_Ransomware.json \
  --gt groundtruth/1_Web_Exploit_Ransomware.groundtruth.json
```

#### 2. 运行全量五折留一端到端交叉验证
```bash
# 纯规则模式五折交叉测试
.venv/Scripts/python.exe provenance-navigator/run_five_fold.py --mode rules

# 智能混合模式五折交叉测试
.venv/Scripts/python.exe provenance-navigator/run_five_fold.py --mode hybrid

# 纯 LLM 模式五折交叉测试
.venv/Scripts/python.exe provenance-navigator/run_five_fold.py --mode llm-only
```
