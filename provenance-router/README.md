# Provenance-Router: 神经符号混合双向因果拓扑与离线知识蒸馏路由系统

---

## 第一部分：目标方案的详细描述 (Target Architecture & Core Mechanisms)

### 1.1 系统定位与前置数据闭环设计

**Provenance-Router** 是面向单主机系统调用日志（Sysdig JSONL）与主机级溯源图（Neo4j）的高性能攻击路径溯源调查与智能路由系统。

针对纯大语言模型（LLM）智能体推理在安全溯源领域存在的**网络延迟高、Token 开销大、判定非确定性、容易在海量静态只读背景边中迷航**的核心痛点，本系统设计了**“神经符号双向因果拓扑初筛与离线知识蒸馏混合路由架构”**（Neuro-Symbolic Dual Causal Topology & Offline Knowledge Distillation with Hybrid Routing）。

本系统的宏观架构依托于一套**数据驱动的对抗演进闭环**：

1. **上游自动化对抗数据源供给**：
   - 系统的技术预设由一个能够自主执行多类型网络渗透与恶意行为的**自动化网络攻击智能体**持续运行，产生大量包含真实背景噪声与高并发系统调用事件的主机日志；
2. **高保真真实攻击路径标注**：
   - 安全分析人员在**预先完全掌握攻击智能体每一步执行逻辑、操作序列与环境配置**的前提下，对照底层系统日志进行人工核验，标注出不存在歧义、具备机器级因果完备性的真实攻击因果路径（标准答案）；
3. **离线蒸馏与知识自适应演化**：
   - 离线知识蒸馏模块作为一个数据驱动的自动化挖掘管道，直接摄取海量对抗日志与高精度标准答案，自动提炼去字面化、跨场景通用的图拓扑因果基模（Motifs），形成持续更新的确定性规则库，为在线调查提供毫秒级高确定性快速通道。

### 1.2 双层双通道协同工作机制

系统整体架构遵循“快慢双通道协同”哲学，划分为三层流水线：

```
                [目标异常事件 (POI: File/Network)]
                                │
                                ▼
        ┌──────────────────────────────────────────────┐
        │ 第 1 层：结构可达因果闭包抽取器 (closure.py)  │
        │ - 直连 Neo4j 图数据库                        │
        │ - 沿进程/文件/套接字反向可达遍历             │
        │ - 产出原始因果候选边集                       │
        └──────────────────────┬───────────────────────┘
                                │
                                ▼
        ┌──────────────────────────────────────────────┐
        │ 拓扑事实索引构建 (TopologyFacts)             │
        │ - 记录入度污染事实 (写入/创建/修改)          │
        │ - 记录出度交付事实 (外联/管道/进程派生)      │
        └──────────────────────┬───────────────────────┘
                                │
                                ▼
        ┌──────────────────────────────────────────────┐
        │ 第 2 层：神经符号智能分流路由器 (router.py)  │
        │                                              │
        │  [通道一：因果初筛通道]                      │
        │   -> 入度无污染 且 出度无交付                │
        │   -> 毫秒级剥离无害只读系统背景至未排除段    │
        │                                              │
        │  [通道二：离线抽象基模快速通道]              │
        │   -> 命中去字面化图因果抽象模式              │
        │   -> 确定性直接确认高危攻击边 (0 次模型调用) │
        │                                              │
        │  [通道三：拓扑歧义度慢速通道]                │
        │   -> 边界模糊候选边按需分流大模型深层仲裁    │
        └──────────────────────┬───────────────────────┘
                                │
                                ▼
        ┌──────────────────────────────────────────────┐
        │ 第 3 层：三段式溯源调查报告生成 (report.py)  │
        │ - edges: 已确认攻击骨干链路                  │
        │ - unexcluded: 安全保留的待查候选集           │
        │ - excluded: 明确排除的噪声背景               │
        │ - stats: 全流程耗时、分流计数与图规模        │
        └──────────────────────────────────────────────┘
```

#### 机制一：双向因果拓扑证据覆盖核验（CausalFilter）
- **核心痛点**：在溯源图反向展开时，进程往往会读取成百上千个系统静态库（如系统公用动态链接库、硬件信息与字库缓存）。这些只读边若直接进入确认段，会导致查准率断崖式下跌；若直接暴力丢弃，又可能误删真正的配置篡改。
- **理论判据**：
  1. **入度无前序污染**：该客体从未被图中任何攻击活动执行过写入（`write`）、新建（`create`）、重命名（`rename`）或权限修改（`chmod`）；
  2. **出度无外部交付**：访问该资源的进程后续没有建立外部网络连接、没有管道外传、没有派生子进程。
- **处理动作**：将此类自闭环无害只读事件毫秒级剥离至未排除段（`unexcluded`），既不破坏图的完整性，又大幅提升确认段的边查准率。

#### 机制二：去字面化的抽象图因果模式蒸馏（PatternMatcher & OfflineDistiller）
- **核心痛点**：依赖大模型做每一跳语义推断代价高昂，而传统专家规则往往充斥着字面量（如硬编码某个特定脚本名），换到新攻击场景即失效。
- **理论判据**：从离线对抗场景中提炼**去字面化（No Literals）的抽象图拓扑因果基模**：
  1. `DIST_01_EXTERNAL_PAYLOAD_EXEC`（载荷落地派生执行）：外部网络写入/落地的文件客体，被后续进程执行执行调用；
  2. `DIST_02_INBOUND_SESSION_SPAWN`（入站会话派生解释器）：入站网络连接套接字被接收后，直接派生系统命令行或脚本解释器；
  3. `DIST_03_PERSISTENCE_SERVICE_MUTATION`（开机持久化与自启动变动）：针对系统服务配置目录、隐藏目录的写入或符号链接变动；
  4. `DIST_04_SENSITIVE_KEY_CHMOD`（敏感客体权限赋予）：对非系统标准路径、临时目录或关键凭据执行权限赋予操作；
  5. `DIST_05_BATCH_MUTATION`（多客体批量覆写破坏）：同一进程短时间内进行高频重命名、删除或批量写入（勒索加密/痕迹清理特征）。
- **处理动作**：若候选池中的边满足抽象拓扑模式，直接确定性升级为已确认边（`confirmed edges`），无需调用大模型。

#### 机制三：快慢双通道智能混合路由（HybridRouter）
- **分流逻辑**：
  1. **快速符号通道（Fast Path）**：通道一初筛与通道二基模匹配，毫秒级处理确定性事件（确认或归入未排除），大语言模型调用量恒为 0 次；
  2. **慢速语义通道（Slow Path）**：初筛未剥离、且基模未覆盖的“高歧义候选边”（如非常规进程间通信、动态脚本反射），智能提取其拓扑因果上下文，按需分流给大模型（LLM Judge）仲裁，兼顾速度与极限泛化。

## 第二部分：现状代码的真实情况 (Current Code Reality & Boundaries)

遵循项目工程规范中的**声明边界法则**与**独立可验证法则**，在此明确当前代码的真实落地深度与客观边界。

### 2.1 声明边界：输入来源与当前运行范围

- **数据源现状**：
  - 目前代码库用于离线蒸馏与测试验证的数据源，为本地归档的 5 个基准网络威胁场景日志（覆盖 Web 漏洞利用勒索、SSH 暴力破解横向移动、钓鱼邮件挖矿木马、代码仓库投毒后门、暴露服务横向枢纽）以及对应的人工标注标准答案；
  - 系统尚未编写与外部攻击智能体运行时的实时动态管道连接脚本，目前采用读取本地归档日志与数据库的方式执行。
- **调查起点（目标异常事件）**：
  - 当前通过配置文件 `config/scenarios.json` 显式声明每个场景的调查起点（POI 事件），路由器直连底层 Neo4j 图数据库，全自主展开反向因果闭包。

---

### 2.2 离线蒸馏器实现现状 (`prouter/offline/distiller.py`)

- **数据驱动实现**：
  - 已彻底移除任何针对特定攻击场景的硬编码文件名、文件路径或特定进程名；
  - 能够自动化遍历训练集真实攻击路径，将实体泛化抽象为语义角色（如被污染进程、网络入站连接、脚本解释器、权限工具、落地文件等），并统计其在全量背景日志中的正常触发次数；
  - 自动依据「跨场景通用支持度」与「抗背景噪声查准率门槛」执行双重淘汰，仅输出高纯度基模供在线模式匹配器加载。
- **当前技术边界**：
  - 当前蒸馏器采用的是**预设候选因果拓扑模式族的统计参数学习与筛选机制**，尚未演进为完全无约束的任意频繁子图自动挖掘算法。

---

### 2.3 在线路由器与双通道实现现状 (`prouter/layers/l2_router/`)

- **快速符号通道（纯规则）**：
  - 因果初筛模块（`causal_filter.py`）与模式匹配模块（`pattern_matcher.py`）协同运转正常；
  - 彻底修复了初筛过度剥离与只读边处理逻辑漏洞，具备毫秒级剥离数千条无害静态库只读边的能力；
  - 在严格的跨场景五折留一盲测中（训练期完全不包含被测场景），支持 100% 独立于大模型执行全图自主调查。
- **慢速语义通道（大模型仲裁）**：
  - 大模型仲裁模块（`llm_judge.py`）与主调度器（`router.py`）已完整实现上下文候选边打包、提示词渲染、多线程并发调用及四值研判映射；
  - 在当前离线大批量性能基准测试中，由于时间与模型资源成本考量，主要评测快速符号通道的基准表现。

### 2.6 快速上手与操作指南

所有操作均在项目根目录虚拟环境中执行：

#### 1. 运行单场景自主调查（直连 Neo4j，端到端执行）
```bash
# 自主连接 Neo4j 展开闭包并执行确定性路由分析，结果输出到 output/agent-runs/<场景全名>.json
.venv/Scripts/python.exe provenance-router/main.py --scenario 1_Web_Exploit_Ransomware

# 运行官方评分工具进行打分
.venv/Scripts/python.exe tools/eval_agent_attack_path.py \
  --report output/agent-runs/1_Web_Exploit_Ransomware.json \
  --gt groundtruth/1_Web_Exploit_Ransomware.groundtruth.json
```

#### 2. 运行全量五折留一端到端交叉验证
```bash
# 自动执行全部 5 折交叉测试（每折均自主连接 Neo4j，由其余 4 个场景蒸馏规则后盲测当前场景）
# 输出详细控制台对照表，并将评测汇总写入 tmp/provenance_router_runs/summary.json
.venv/Scripts/python.exe provenance-router/run_five_fold.py
```
