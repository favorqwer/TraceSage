清单字段说明（边行与其下的缩进行都按这套口径读）：
- 折叠事件数：这条边由多少条原始事件折叠而来；一条边只能给一个结论；折叠事件之间可能混有正常与恶意行为，按整体主导性质判断。
- 字节：只对搬运数据的操作（读、写、收、发）有意义；这类操作显示 0 表示本次实际搬运了 0 字节（例如读到结尾）。
  启动新程序、派生、建立连接、改名、改权限、创建/删除等操作的返回值是状态码、不是字节数，一律按 0 记录；0 不代表"没有发生行为"。
  折叠后显示的是多个折叠事件的累计值。
- 时间：多个折叠事件里最早的开始时刻到最晚的结束时刻，相对"时间原点"的秒数；负号表示早于目标事件。
  启动新程序、派生这类边的结束时刻会被延长到父进程最后一次被观察到的时刻，可能晚于目标事件；判断先后只看开始时刻。
- 进程：边的归属进程（标识 + 程序/路径）；进程表给出它的命令行、工作目录、来源和活动区间。
- 本会话命令活动（只在属于某次服务会话的记录上出现）：一个进程接受一次连接算一次会话，会话里可能
  有好几个进程。这个数字表示这次会话里由非服务进程（shell、命令等，不含服务进程自己）在本次清单里
  留下了多少条记录；0 表示这次会话除连接本身与自身的读写之外没有命令活动。同一个服务进程可能接受

对象端点的特殊写法：
- "pipe:[编号]" 表示管道：内容由一端进程写入、另一端进程读出，管道本身不产生内容；
- "unix:[路径]" 表示本机套接字：按文件系统路径标识，用于同一台主机内的进程间通信；
- /proc、/sys 下内核现生成的文件、/dev 下的设备节点（含终端）、/run（含 /var/run、/var/lock）这类系统运行目录及其中的套接字，属于非交付通道：只收集"读取它"的边、不往上追溯写入者（/proc/进程号/ 下的读边连边都不收集），所以清单里看不到它的写入方；
- 网络端点写成"本地地址:端口->远端地址:端口"；协议有记录时在端点后用括号补出（例如 tcp、udp；同一端点出现不同协议时按首个记录显示，没记录就不写）。
