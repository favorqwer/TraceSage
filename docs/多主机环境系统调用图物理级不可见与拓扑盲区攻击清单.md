# 多主机环境系统调用图物理级不可见与拓扑盲区攻击清单

> **制定依据**：基于操作系统内核陷入机制、分布式因果溯源图理论、系统调用审计边界、DARPA Transparent Computing（TC）项目评估结论及 MITRE ATT&CK 威胁矩阵。  
> **工程法则**：严格遵循《AGENTS.md》第一部分“声明边界法则”与“阻断诚实法则”。任何基于主机系统调用日志（如 Sysdig SCAP、Linux Auditd、Windows Sysmon/ETW）构建的图谱，均存在不可逾越的物理陷入天花板与分布式拓扑边界。

---

## 一、 核心物理边界与双重观测天花板

在多主机环境系统调用溯源图（Multi-host Provenance Graph）中，攻击活动能否被图谱捕获，取决于两层独立判据：
1. **单机物理陷入天花板**：操作是否触发了 CPU 陷入内核态的系统调用指令；
2. **分布式拓扑缝合边界**：跨网络端点是否在统一命名空间下具备双向对称的四元组映射且相关主机均已纳管。

### 1. 操作系统内核陷入物理天花板（单机物理层）

系统调用（System Call，简称 syscall）是用户态应用程序向操作系统内核请求硬件与系统资源（如读写文件、发送网络报文、派生子进程）的**唯一合法 CPU 陷入指令**。探针（如 Sysdig 内核驱动）的捕获点固定在内核派发系统调用的瞬间。

凡是**在陷入内核之前已完成**、**在网卡硬件/底层驱动层被静默丢弃**、**纯在虚拟内存空间内部计算**、**在线缆与外部网络设备上发生**的操作，在单机系统调用图上均为**物理级不可见（0 字节日志、0 个顶点、0 条边）**。

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   【网络与硬件物理世界】 (物理不可见)                   │
│      光纤分光 / 交换机投毒 / ARP 欺骗 / 远端多跳代理 / 硬件 DMA         │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│                   【网卡硬件与驱动底层】 (物理不可见)                   │
│      RingBuffer 溢出 / Netfilter-XDP 丢弃 / SYN Cookies / 畸形分片     │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│                   【内核网络栈与 VFS 缓冲】 (部分可见)                 │
│      Socket 缓冲区 / 本机回环协议栈 / VFS 虚拟文件接口抽象              │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │
═══════════════════════════════════╪══════════════════════════════════════ ◄── 【物理观测天花板】(系统调用捕获点)
                                   │
┌────────────────────────────────────────────────────────────────────────┐
│                   【操作系统系统调用接口】 (仅此处可见!)               │
│      sys_enter -> 系统调用派发 -> sys_exit (Sysdig / Sysmon 探针)      │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │
═══════════════════════════════════╪══════════════════════════════════════
                                   │
┌────────────────────────────────────────────────────────────────────────┐
│                 【用户态进程虚拟内存空间】 (物理不可见)                 │
│      CPU 寄存器操作 / ROP 内存链执行 / 纯内存计算 / 用户态加密解密      │
└────────────────────────────────────────────────────────────────────────┘
```

### 2. 多主机分布式因果拓扑缝合机制（多机拓扑层）

在多主机环境中，系统调用图通过引入主机命名空间属性（`node.host_id`）并共享网络端点（`:Network` 节点，基于升序对齐的通信四元组 `src_ip:src_port <-> dst_ip:dst_port`）来自然缝合跨主机横向移动：

```text
【主机 A: host-1】                                          【主机 B: host-2】
┌───────────────────────┐                                 ┌───────────────────────┐
│   :Process 节点       │                                 │   :Process 节点       │
│   host_id: "host-1"   │                                 │   host_id: "host-2"   │
│   name: "ssh"         │                                 │   name: "sshd"        │
└──────────┬────────────┘                                 └───────────▲───────────┘
           │                                                          │
           │ [:p2n]                                                   │ [:n2p]
           │ action: "connect"                                        │ action: "accept"
           ▼                                                          │
   ┌──────────────────────────────────────────────────────────────────┴────────┐
   │                              :Network 节点                                │
   │                  192.168.1.10:45210 <───> 192.168.1.20:22                 │
   └───────────────────────────────────────────────────────────────────────────┘
```

- **全受管闭环状态**：当通信两端主机均安装探针、时钟同步正常且无网络地址转换篡改时，跨主机横向移动因果拓扑**完全闭环且自主可见**。
- **拓扑断裂状态**：当存在中间地址重写、外部未纳管跳板、容器隧道封装或时间乱序时，图谱在网络节点处发生断裂。

## 二、 单机物理陷入绝缘的五大类共 25 种攻击清单

无论系统扩展至多少台主机，以下 25 种攻击由于受制于单机系统调用物理陷入机制，在任一受管主机上均产生 0 条系统调用日志，属于恒定的物理观测盲区。

### 第一类：链路层与网络基础设施攻击（在网卡与线缆层发生，完全不穿透至主机系统调用）

| 编号 | 攻击类型 (ATT&CK ID) | 技术原理与物理机制 | 为什么系统调用图物理不可见？ | 建议防御与补充观测源 |
|---|---|---|---|---|
| **C1-01** | **ARP 缓存投毒与欺骗**<br>(T1557.002) | 攻击者在局域网发送无应答伪造 ARP 报文，恶意篡改受害机操作系统内核 ARP 缓存表中的网关 IP-MAC 映射。 | 攻击由底层协议栈直接更新内核 ARP 缓存，**不产生任何用户态系统调用**。 | 交换机动态 ARP 检查 (DAI)、静态 ARP 绑定、网络探针。 |
| **C1-02** | **MAC 地址泛洪与交换机投毒**<br>(T1040) | 向局域网高频发送大量伪造随机 MAC 帧，耗尽交换机 CAM 内存，迫使交换机降级为 Hub 广播模式以嗅探流量。 | 操作作用于局域网物理交换机芯片，受害主机系统调用层为物理真空。 | 交换机端口安全配置 (Port Security)、802.1X 接入认证。 |
| **C1-03** | **DHCP 饥饿与流氓 DHCP 攻击**<br>(T1557) | 耗尽合法 DHCP 池并伪造虚假网关与恶意 DNS 服务器地址分发给受害主机。 | 客户端通常仅在网络初始化时交互，二层配置篡改本身无系统调用恶意特征。 | 交换机 DHCP Snooping。 |
| **C1-04** | **BGP 路由劫持与路由泄露**<br>(T1584.004) | 恶意 AS 广播更优前缀诱导公网路由器将受害主机流量重定向流经攻击者节点。 | 操作系统发起正常的 TCP 握手与通信，系统调用看到的是合法 IP，路由偏航在自治系统间完成。 | RPKI 路由原发验证、BGP 监控告警。 |
| **C1-05** | **生成树协议伪造劫持 (STP Attack)**<br>(T1557) | 伪造高优先级 BPDU 报文抢占二层网络根桥，强制重构广播树以旁路嗅探。 | 协议完全作用于交换机控制面，主机系统调用层零感知。 | 交换机启用 BPDU Guard / Root Guard。 |
| **C1-06** | **VLAN 越界穿透 (VLAN Hopping)**<br>(T1557) | 攻击者利用双层 802.1Q 标签（Double Tagging）跨越虚拟局域网安全隔离。 | 标签剥离发生在第一跳交换机硬件，进入主机网卡时已被还原为普通数据帧。 | 禁用未使用的 DTP 端口、隔离 Native VLAN。 |
| **C1-07** | **物理光纤分光与被动窃听**<br>(T1040) | 在物理网络线路上串接光纤分光器（Optical TAP）无差别镜像复制传输流量。 | 纯物理光学/电学信号复制，对主机网卡和操作系统内核零负载、零中断。 | 端到端全链路强加密通信 (TLS 1.3 / IPsec)。 |

### 第二类：报文级网络/传输层拒绝服务（在进入 Socket 抽象层前被丢弃）

| 编号 | 攻击类型 (ATT&CK ID) | 技术原理与物理机制 | 为什么系统调用图物理不可见？ | 建议防御与补充观测源 |
|---|---|---|---|---|
| **C2-01** | **TCP SYN 泛洪攻击**<br>(T1498.001) | 发送海量伪造源 IP 的 SYN 半开握手请求，耗尽主机 TCP 半连接队列（`tcp_max_syn_backlog`）。 | 当内核启用 SYN Cookies 或被 Netfilter/iptables 丢弃时，**完全不会触发应用程序的 `accept` 系统调用**。 | 内核 SYN Cookies、XDP/eBPF 高性能报文丢弃、硬件 Anti-DDoS。 |
| **C2-02** | **UDP 反射放大泛洪**<br>(T1498.002) | 利用 NTP/DNS/SSDP 等无状态服务反射放大数百倍的高频单播 UDP 报文打满带宽。 | 报文灌满网卡环形缓冲区（Ring Buffer）直接硬件丢包，根本无法上传至 Socket 缓冲区。 | 上游流量清洗中心、Anycast BGP 分流。 |
| **C2-03** | **死亡之 Ping 与重叠分片**<br>(T1498) | 发送超大畸形 ICMP 包或带有重叠偏移的 IP 分片（Teardrop），使内核重组逻辑崩溃。 | IP 分片重组由操作系统内核网络协议栈底层直接处理，在未完成重组前不产生系统调用。 | 操作系统内核网络栈补丁、网络层清洗。 |
| **C2-04** | **Land 攻击 (同源同宿回环风暴)**<br>(T1498) | 发送源 IP、源端口与目的 IP、目的端口完全相同的畸形 TCP 报文。 | 在内核 TCP 状态机处直接被 RST 复位或丢弃，不进入应用层。 | 操作系统内核防御机制、安全组规则。 |
| **C2-05** | **慢速 DoS 的反代边界截断**<br>(T1499.003) | 攻击者以极慢速度发送 HTTP 请求头（Slowloris），长期占用连接句柄。 | 若主机前端部署了反向代理（Nginx/HAProxy/WAF），恶意连接在接入层被超时掐断，后端进程完全无感。 | 反向代理超时收敛、连接速率限制。 |

### 第三类：应用层语义与加密载荷攻击（系统调用只看到合法读写，看不到应用内部逻辑破坏）

| 编号 | 攻击类型 (ATT&CK ID) | 技术原理与物理机制 | 为什么系统调用图物理不可见？ | 建议防御与补充观测源 |
|---|---|---|---|---|
| **C3-01** | **SQL 注入攻击**<br>(T1190) | 攻击者在 Web 请求中注入 `' OR 1=1 --` 语法树破坏数据库结构。 | 数据库服务（如 `mysqld`）在内核层面只是正常的 `read(socket)`、正常的 `read(file.ibd)` 并正常返回，系统调用层毫无异常。 | WAF、数据库审计日志、预编译参数化查询 (ORM)。 |
| **C3-02** | **跨站脚本攻击 (XSS)**<br>(T1189) | 存储型或反射型恶意 JS 脚本被 Web 服务器持久化存储并渲染发给浏览器。 | 服务器仅是正常执行文本字符串的读取与网络发送，系统调用图看不到 HTML 内嵌套的恶意脚本。 | 网页输出编码、Content Security Policy (CSP)。 |
| **C3-03** | **越权访问与直接对象引用 (IDOR)**<br>(T1530) | 普通用户 A 篡改参数下载普通用户 B 的私密账单文件。 | 服务器正常执行 `open()` 和 `read()`，在系统调用图上仅表现为合法的白名单文件读取。 | 应用层权限校验框架、RBAC/ABAC。 |
| **C3-04** | **服务端请求伪造 (SSRF)**<br>(T1090) | 诱导服务端向内网其他 API 或元数据地址（`169.254.169.254`）发起请求。 | 系统调用仅体现为普通的 `connect()` 与 `sendto()`，在没有细粒度网络策略时与正常业务微服务通信无异。 | 内部网络严格隔离、禁用高危协议。 |
| **C3-05** | **TLS/HTTPS 加密通道内载荷隐藏**<br>(T1573.002) | 攻击流量经 TLS 强加密传输，WebShell 或木马指令在用户态库（OpenSSL）完成解密。 | 内核探针在 `recvfrom` 处捕获的全部是高熵加密密文，无法理解指令含义。 | eBPF 用户态挂钩（Uretprobes 挂载 SSL_read）、反向代理解密镜像。 |
| **C3-06** | **DNS 隧道隐蔽信道外发**<br>(T1071.004) | 将机密数据编码在多级子域名中向外部 DNS 解析器发送查询。 | 底层仅表现为向 `127.0.0.53:53` 发送的标准 UDP 报文，系统调用图看不见域名长编码载荷。 | DNS 流量解析日志、DGA/长域名熵值分析。 |

### 第四类：纯用户态内存、寄存器与微架构攻击（完全在虚拟地址空间执行，不陷入内核）

| 编号 | 攻击类型 (ATT&CK ID) | 技术原理与物理机制 | 为什么系统调用图物理不可见？ | 建议防御与补充观测源 |
|---|---|---|---|---|
| **C4-01** | **返回导向编程 (ROP / JOP 链)**<br>(T1055) | 覆盖栈返回地址，串联内存中现有的 Gadget 指令操控 CPU 寄存器。 | 整个利用链完全在用户态内存与 CPU 寄存器间流转，在最终调用特权系统调用前，系统调用记录为 0。 | 编译器开启 CET (Control-flow Enforcement Technology)、ASLR、DEP。 |
| **C4-02** | **纯用户态堆喷射与内存覆写**<br>(T1055) | 在进程堆中喷射海量构造对象并改写虚函数表指针。 | 仅消耗 CPU 计算与内存总线，不产生任何与内核交互的系统调用。 | 内存分配器加固 (DieHarder)、严格边界检查。 |
| **C4-03** | **CPU 侧信道窃密 (Spectre / Meltdown)**<br>(T1592.004) | 利用 CPU 乱序执行与分支预测机制，通过 Cache 访问时差窃取内核或进程隔离数据。 | 攻击发生于 CPU 硬件执行流水线和 Cache 控制器，操作系统完全无感知。 | CPU 微码更新、内核 KPTI 页面隔离。 |
| **C4-04** | **物理行锤击物理击穿 (Rowhammer)**<br>(T1068) | 以纳秒级高频反复访问相邻 DRAM 物理行，诱发电容电荷泄露产生位翻转。 | 纯硬件物理电磁干扰，操作系统内核与探针完全无法监控物理电容状态。 | 使用带 ECC 纠错功能的物理内存、TRR 刷新机制。 |
| **C4-05** | **直接内存访问 (DMA) 硬件攻击**<br>(T1200) | 攻击者利用恶意 PCIe、雷电（Thunderbolt）接口硬件直接读写物理内存。 | 硬件总线控制器直接旁路 CPU 和操作系统内核，系统调用层毫无记录。 | 启用 IOMMU (Intel VT-d / AMD-Vi)、禁用不信任的外设总线。 |

### 第五类：内核级底层 Rootkit 与探针篡改（在系统调用捕获点前抹除痕迹）

| 编号 | 攻击类型 (ATT&CK ID) | 技术原理与物理机制 | 为什么系统调用图物理不可见？ | 建议防御与补充观测源 |
|---|---|---|---|---|
| **C5-01** | **系统调用表挂钩 (Syscall Hooking / DKOM)**<br>(T1014) | Ring 0 内核模块直接修改 `sys_call_table` 函数指针，隐藏进程与连接。 | 审计模块与探针位于内核中，若探针本身被底层恶意驱动 Hook，上报数据被直接截杀。 | 启用 UEFI 安全启动、锁定内核模块加载 (`modules_disabled`)。 |
| **C5-02** | **恶意 eBPF 程序劫持 (eBPF Rootkit)**<br>(T1014) | 攻击者加载特权 eBPF 程序，在 Tracepoints 触发前修改数据或阻断探针调用。 | eBPF 程序在内核上下文先于审计探针运行，具有对内核内存的原生篡改能力。 | 限制 `CAP_BPF` 权限、审计 eBPF 字节码加载。 |

## 三、 分布式多主机环境特有的七大拓扑盲区与断裂边界

在多主机环境下，因果图谱通过网络通信端点（`:Network` 节点）拼接跨机因果链。当网络拓扑跨越不可控边界、经过地址转换与容器封装中间件、跨越解耦存储或由于物理晶振误差导致时序失真时，会产生以下 7 类分布式特有图谱盲区：

| 编号 | 盲区类型 (ATT&CK ID) | 技术原理与分布式物理机制 | 为什么因果图谱产生断裂/不可见？ | 建议防御与补充观测源 |
|---|---|---|---|---|
| **M-01** | **NAT 与负载均衡四元组撕裂**<br>(T1090) | 主机 A 发往主机 B 的网络流途经 NAT 网关、F5、Nginx 或云厂商四/七层 SLB，源 IP/端口或目的 IP/端口被重写。 | 主机 A 记录的远端端点（如 `SLB_VIP:80`）与主机 B 记录的本地端点（如 `RealServer_IP:8080`）**无法在 Neo4j 中归一为同一个 `:Network` 顶点**，导致出站 `p2n` 边与入站 `n2p` 边断开。 | 接入代理层全链路日志注入 Trace-ID、eBPF 网络层连接跟踪 (conntrack) 映射。 |
| **M-02** | **影子 IT 与未受管跳板节点穿透**<br>(T1021) | 攻击者从已受管主机 A 横向移动至未安装探针的跳板机 X，再从跳板机 X 登录至受管主机 B。 | 跳板机 X 无系统调用采集（0 日志），因果图上仅能看到孤立的“A 外联 X”与“B 接收 X”，**无法自主建立 A 到 B 的控制流传递因果**。 | 主机资产准入基线检查、全网段探针强制覆盖。 |
| **M-03** | **跨物理机时钟漂移与因果倒流**<br>(T1070.006) | 分布式集群中各物理节点 NTP/PTP 时间同步存在毫秒级甚至秒级漂移。 | 若主机 B 的 `accept` 事件时间戳由于时钟偏慢而**早于主机 A 发起 `connect` 的时间戳**，因果遍历算法的时序因果约束判定失效，真实攻击边被当作“时间倒流”而剔除。 | 高精度硬件时钟同步 (IEEE 1588 PTP)、容忍合理时钟漂移的因果软约束窗。 |
| **M-04** | **外部非受管源与前置阻断海量试探**<br>(T1110.001) | 外部黑客对公网受管服务发起数十万次密码尝试，被前置 WAF 或堡垒机阻断，最终 1 次成功穿透。 | 前序试探发起源在公网且被上游设备拦截，未穿透至受管主机内核 Socket；受管主机系统调用图仅记录该次成功的连接，**外部海量前序探测全貌缺失**。 | 统一 SIEM / XDR 汇聚边界防火墙与堡垒机审计日志。 |
| **M-05** | **公网非纳管匿名代理与多跳跳板 (Tor)**<br>(T1090.003) | 攻击者通过公网洋葱路由（Tor）或商业代理池的多层转发向受管主机集群发起渗透。 | 受管集群边界只能捕获最后一跳代理出口 IP，公网不可控多跳路由在物理上无法部署探针，**真实攻击源的前序拓扑天然断裂**。 | 威胁情报 IP 声誉画像、公网 NetFlow 流量关联。 |
| **M-06** | **容器虚拟化网络重叠与 Overlay 封装**<br>(T1021) | 跨宿主机容器网络使用重叠私网 IP（如各宿主机均有 `172.17.0.2` 容器），跨机通信经由 VXLAN (UDP 4789) / Calico 隧道封装。 | 若按容器内 IP 建点会导致不同主机的无关容器被**错误合并为一个 `:Network` 超节点（身份混淆）**；若按宿主机外层建点，容器间真实的通信流向被 UDP 隧道隐藏，**容器级横向移动拓扑断裂**。 | Kubernetes CNI 拓扑元数据映射、eBPF 网络命名空间 (NetNS) 跨层解包追踪。 |
| **M-07** | **分布式共享存储 (NFS/Ceph) 读写解耦**<br>(T1021.002) | 主机 A 恶意进程将载荷写入共享网络文件系统挂载点；主机 B 随后通过挂载点读取并执行该文件。 | 主机 A 与主机 B 之间**没有任何直连的网络 Socket 边（无 `connect`/`accept`）**，控制流在网络层完全解耦，系统调用图上表现为两台互不相干的孤立主机，**无法通过网络直接遍历回溯**。 | 分布式存储集群服务端审计日志、跨主机文件内容哈希 (Hash) 与 Inode 因果对齐。 |

## 四、 结论与工程底线声明

在进行多主机环境威胁溯源系统（TraceSage）的设计与评测时：
1. **严禁虚假宣称 100% 还原攻击**：上述第一至第五类共 25 种单机物理绝缘攻击以及第三部分 7 种分布式拓扑盲区，属于系统调用图的客观边界。
2. **严格区分单机与多机可见性**：
   - 受管集群内部的直连跨主机横向移动（如受管主机 A 经由 SSH 登录受管主机 B）**已具备完整的端到端图谱因果闭环能力**；
   - 凡涉及 NAT 地址转换、未纳管节点跳板、公网匿名多跳、Overlay 隧道隐藏或共享存储解耦的链路，必须遵循「阻断诚实法则」，主动声明拓扑断裂边界，绝不使用人工假设或虚假边强行缝合。
3. **多维融合取证**：针对上述盲区，必须依靠网络全流量（NTA/NDR）、Web 应用防火墙（WAF）、应用日志（Application Logs）及硬件审计设施进行立体化融合取证。
