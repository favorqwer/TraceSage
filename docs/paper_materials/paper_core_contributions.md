

## 四. 核心创新点一：受因果拓扑硬约束的神经-符号协同调查架构
*(Topology-Constrained Neuro-Symbolic Reasoning Architecture)*

```
┌─────────────────────────────────────────────────────────────────────────────────────────────────┐
│                           受因果拓扑约束的神经-符号调查数据流流水线                              │
└─────────────────────────────────────────────────────────────────────────────────────────────────┘
  原始图输入               第一层：行为抽象表征          第二层：双轨知识解耦            第三层：受控推理与守卫
┌──────────────┐         ┌──────────────────────┐      ┌─────────────────────────┐     ┌───────────────────────┐
│ 系统调用审计 │ 闭包抽取 │ 上下文感知行为抽象   │ 检索 │ 轨1: 微观因果转移基模   │ 注入  │ 神经语义判决          │
│ 事件流 (DAG) │────────>│ (四元组行为单元构建) │─────>│ 轨2: 宏观战术本体先验   │────>│ (意图推断与四选一裁决) │
└──────────────┘         └──────────────────────┘      └─────────────────────────┘     └───────────┬───────────┘
                                                                                                   │ 校验跳链/标识
                                                                                                   ▼
                                                                                       ┌───────────────────────┐
                                                                                       │ 状态机引用守卫验证    │
                                                                                       │ [合法] 确认攻击因果链 │
                                                                                       │ [非法] 强制安全降级   │
                                                                                       └───────────────────────┘
```

### 1. 形式化问题定义与学术痛点
主机审计日志构成因果有向无环图 `G = (V, E)`：
- 顶点集合 `V`：包含进程主体（Process）、文件资源（File）、套接字网络端点（Network）；
- 有向边集合 `E`：每条边 `e = (u, v, sc, t)` 代表源实体 `u` 在时间戳 `t` 通过系统调用操作 `sc` 作用于目标实体 `v`。

**根本学术痛点**：
1. **依赖爆炸（Dependency Explosion）**：从警报实体 `v_alert` 反向追踪因果闭包时，系统调用的高频并发导致候选边规模剧增（10^5 到 10^7 条），直接输入模型超出了上下文长度极限；
2. **因果幻觉（Causal Hallucination）**：通用大模型作为概率生成模型，缺乏对底层操作系统因果状态转移的物理约束，容易在非连通实体间臆造虚假攻击因果链，破坏了司法级调查的可靠性。

### 2. 核心技术机制展开

#### 机制 A：上下文感知的因果行为抽象表征（Context-Aware Behavioral Abstraction）
- **核心算法**：
  在原始因果边上定义条件等价关系 `~B`：
  两条因果边 `e1, e2` 若具备相同的进程镜像名、因果流向、系统调用动作名称、以及目标资源类别四元组，则属于同一等价类。
  系统将原始图 `G` 映射为行为单元集合 `B = G / ~B`。
- **因果可达性保持定理（Causal Reachability Theorem）**：
  若原始图存在因果路径 `P = <e1, e2, ..., ek>`，在抽象后的行为图上必然存在等价连续路径，不损失任何攻击连通性。
- **效果**：将高层推理面对的分析规模压缩 90% 以上。
- **代码对应**：`provenance/core/bundling.py`（五级层次化聚合）与 `provenance/core/gates.py`（前置拓扑结构闸门）。

#### 机制 B：多源异构威胁知识的双轨正交解耦对齐（Decoupled Dual-Track Knowledge Retrieval）
- **核心算法**：
  将安全知识正交解耦为独立的两轨，分别建立图索引：
  1. **微观因果转移基模轨（Microscopic Causal Motifs, R）**：检索底层图挖掘出的频繁因果子图跳链，三元组为 `<源角色, 系统调用, 目标角色>`，刻画微观拓扑转移规律；
  2. **宏观威胁情报本体轨（Threat Intelligence Ontology, E）**：检索 MITRE ATT&CK 行为观测本体，刻画专家级宏观攻击意图；
- **解耦优势**：两轨采用独立的命名空间（R_x 与 E_y），独立度量匹配置信度，防止底层统计特征与高层语义产生相互掩盖。
- **代码对应**：`provenance/rag/graph_retrieve.py` 中的 `exact_motifs` 与 `technique_entry`。

#### 机制 C：基于后验状态机的因果事实验证与安全降级（Fact-Grounded Verification & Graceful Degradation）
- **核心算法**：
  大模型对每个候选行为单元输出结构化判定：
  ```text
  Verdict in {all (整单元确认), none (整单元排除), mixed (未决混杂), unknown (信息不足)}
  Citation = <Rule_ID, Hop_ID, Tech_ID>
  ```
  后验验证状态机执行确定性求值：
  ```text
  验证通过条件：
  (Hop_ID 属于 Rule_ID 包含的真实跳链) 
  AND (Hop_ID 对应的系统调用 == 行为单元物理执行的系统调用) 
  AND (行为单元两端实体角色模式与 Hop 角色模式一致)
  ```
  - **安全降级策略**：若模型判定为 `all`，但未引用跳链、引用了不存在的编号、或引用的跳链系统调用与实际不符，状态机立即判定校验失败，强制触发安全降级算子，将该行为单元重置为 `mixed` 态并在下一轮细化分支中继续验证。
- **学术价值**：**从机制上消除了大语言模型在安全调查中的凭空捏造，实现输出图严格的零虚假跳链（Zero False Hops）。**
- **代码对应**：`provenance/llm/judge.py` 与 `provenance/core/stages/s4_decision.py`。

## 五. 核心创新点二：基于轻量状态重放的增量式因果基模同化机制
*(Zero-Requery Incremental Causal Ingestion via Scenario Bitmasks)*

```
┌─────────────────────────────────────────────────────────────────────────────────────────────────┐
│                            零重查增量式因果基模同化机制架构                                     │

┌──────────────────────┐                                           ┌─────────────────────────────┐
│ 变异场景日志 (S_new) │                                           │ 预计算紧凑场景位图掩码      │
└──────────┬───────────┘                                           │ (Scenario Bitmasks)         │
           │                                                       └──────────────┬──────────────┘
           ▼                                                                      │
┌──────────────────────┐                                                          │
│ 单次局部因果子图抽取 │                                                          │
│ 与候选基模挖掘       │ 产生候选基模集合 {M_cand}                                │
└──────────┬───────────┘                                                          │
           │                                                                      │
           ▼                                                                      ▼
┌────────────────────────────────────────────────────────────────────────────────────────────────┐
│ 内存位图逻辑重放引擎 (Bitwise Logical Replay Engine)                                           │
│ 零图数据库重查，在内存中执行位逻辑运算：Hits(M_cand) = Bitwise_Replay(M_cand, Historical_Bitmasks) │
└────────────────────────────────────────────────┬───────────────────────────────────────────────┘
                                                 │ 快速生成覆盖表与查准率统计

                                 ┌───────────────────────────────┐
                                 │ 边际增益贪心集合覆盖准入      │
                                 │ 动态扩展核心防御基模库        │
                                 └───────────────────────────────┘
```

### 1. 形式化问题定义与学术痛点
面对高级变异威胁，攻击者常通过等价系统调用代换（如以内存映射代换普通写操作）或插入伪造中间进程打散因果链：
- **静态规则库衰减**：既有离线挖掘的基模在攻击拓扑发生变异后迅速失效；
- **全量重训计算爆炸**：传统频繁子图挖掘算法在接入新场景时，必须重新加载历史全部场景执行全图图同构遍历，时间开销随历史场景数量线性增加，导致防御系统无法在线快速进化。

### 2. 核心技术机制展开

#### 机制 A：基于紧凑位图掩码的场景状态表征（Bitmask-Based Scenario Representation）
- **核心算法**：
  初次解析历史场景时，将系统调用边的命中状态离散化并压缩为位向量（Bitmaps）：
  - 每个历史场景对应一个轻量分片（`ScenarioShard`）；
  - 每条边的匹配状态与正负样本标签表示为定长位掩码，将数个 GB 的复杂图结构降维为内存中百 KB 级的位矩阵。
- **代码对应**：`provenance/rules/coverage.py` 中的 `CoverageStore` 与 `ScenarioShard`。

#### 机制 B：零图数据库重查的增量同化算法（Zero-Requery Incremental Ingestion）
- **核心算法**：
  当新攻击场景 `S_new` 到达时：
  1. **单次局部抽取**：仅对新场景 `S_new` 连接图数据库执行单次局部因果图抽取，挖掘产生候选基模集合 `M_cand`；
  2. **内存位逻辑重放**：对历史所有场景，**物理图查询次数严格为 0**。算法仅读取内存中的历史场景位图掩码，通过 CPU 级别的位逻辑代数重放，在毫秒内完成候选基模在所有历史场景中的查准率与覆盖率评估；
  3. **计算复杂度**：从全局重新挖掘的超线性复杂度下降为 `O(|E_new| + k * BitOps)`。
- **代码对应**：`provenance/rules/offline.py` 中的 `ingest` 函数与 `replay_missing` 接口。

#### 机制 C：带边际效用优化的贪心集合覆盖准入（Marginal-Utility Greedy Admission）
- **核心算法**：
  准入优化目标：在最大化变异攻击覆盖的同时，严格抑制良性误报并控制规则库容量：
  ```text
  Max: Coverage(M_selected, Positive_Edges) 
       - lambda * FalseHits(M_selected, Negative_Edges) 
       - gamma * |M_selected|
  ```
  通过贪心迭代，准入具有最高边际覆盖增益的最小基模子集，保证规则库规模平稳收敛。
- **代码对应**：`provenance/rules/admission.py`。

## 九. 核心实验三：典型攻击案例复原（Case Study - 场景 8 导出方案）

### 1. 为什么选择场景 8 作为 Case Study 黄金案例？
- **步骤召回率**：**95.2%**（60 / 63 步全部命中）；
- **边级查准率**：**81.2%**（输出 697 条边中，566 条为真实攻击边）；
- **输出边数规模紧凑**：仅 **697 条边**，彻底免除了传统方法上万条边缠绕成团的弊端；
- **攻击因果逻辑层层递进**：覆盖从外部口令喷洒、WebShell 落地、命令派生、敏感文件收集到通过 curl 隐蔽渗出的完整 APT 全生命周期。

### 2. 真实攻击链路的结构化梳理（论文正文配文）
```text
【步骤 ①：网络探测与弱口令爆破 (Initial Access)】
外部攻击源（IP: 100.74.213.15）向靶机 21 端口发起连接，对 vsftpd 守护进程实施暴力破解并成功获取会话凭据。

【步骤 ②：恶意载荷上传 (Payload Delivery)】
攻击者通过 FTP 会话执行底层 write 系统调用，将恶意 PHP 脚本 (webshell.php) 写入 Web 开放目录 /var/www/html/。

【步骤 ③：WebShell 触发与命令派生 (Execution)】
攻击者转而向 Web 服务器发送 HTTP 请求访问 webshell.php；Web 进程 (apache2/php) 派生 (fork/execve) 出系统 shell 进程 (/bin/bash)。

【步骤 ④：敏感凭据收集与打包 (Collection)】
攻击者通过 bash 执行命令收集敏感配置，并调用系统归档工具将敏感凭据打包至临时目录 /tmp/。

【步骤 ⑤：网络隐蔽外发 (Exfiltration - 告警锚点 POI)】
攻击者执行 /usr/bin/curl 命令，调用 sendto 系统调用向外部恶意服务器 (100.74.213.15:8888) 传输数据包，触发网络异常告警。
本文系统以该 curl 的 sendto 边作为调查起点，成功反向穿透 bash、php 以及 vsftpd，完整复原了全流程因果链。
```
