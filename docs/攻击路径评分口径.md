# 攻击路径评分口径（必须集合 / 可能集合）

范围：只评「入口事件 → 终点事件（POI）」之间的攻击路径。标准答案把这段路径拆成若干**步骤**，每个步骤写进**必须集合**（逐条条目）或**可能集合**（规则）；方法输出一组边。比较单位是**内容三元组**（源内容、系统调用、目标内容）。**召回按步骤算，查准按边算。**

---

## 一、标准答案

### 1.1 步骤

- 按时间顺序分成步骤，一步等于攻击路径上的一环。
- 一个步骤里哪些三元组算「同一种效果」，做标准答案时对着攻击复现文件逐个确定，并把结论写进标准答案：每个条目或规则都要能指回它属于哪一步、从哪次复现收出来。
- **步骤总数 = 必须集合的条目数 + 可能集合的规则数。**

### 1.2 必须集合（条目）

- 这一步的三元组不随环境变化 → **逐条列出**源、系统调用、目标三部分。
- 同一三元组发生多次只列一条（按内容去重，不按实例）。
- 字段：`edge_id`、`src`、`syscall`、`dst`。

### 1.3 可能集合（规则）

- 这一步的三元组条数随机器环境变化（典型：目标清单由脚本当场扫描得出） → 每个这样的步骤写**一条规则**。
- 一条规则 = 三段条件 + 若干记账字段：

| 字段 | 含义 |
|---|---|
| `source` | 端点条件，绑在边的**源端** |
| `action` | 系统调用名列表 |
| `target` | 端点条件，绑在边的**目标端** |
| `direction` | `src_to_dst`（默认，按上面的绑定）｜`either`（两端任一方向都算） |
| `edge` | 可选。边自身属性的数值条件，如 `{"bytes": {"op": ">=", "value": 1024}}`（`op` 取 `>=`／`>`／`<=`／`<`／`=`／`!=`）。**只筛实例，不改变三元组命中集合** |
| `covered_triples` | 本场景窗口内、按内容三元组去重后满足全部条件的边数（实测值，只记账，不参与判定） |

### 1.4 端点条件（`source` / `target` 的形状）

叶子字段：

| 字段 | 取值 |
|---|---|
| `vertex` | `process`｜`file`｜`network`｜`any`（缺省 `any`＝不限种类） |
| `match` | `any`（任意值）｜`exact`（等于 `value`）｜`in`（在 `values` 里）｜`path_prefix`（路径以 `value` 开头）｜`path_suffix`（路径以 `value` 结尾）｜`path_pattern`（路径按 `value` 里的正则匹配） |
| `value` / `values` | 与 `match` 配套的单个值／值列表 |

组合字段（可与叶子字段同现；同现时先算组合字段，叶子按「且」叠加）：

| 字段 | 含义 |
|---|---|
| `all_of` | 列表：全部子条件都要满足（且） |
| `any_of` | 列表：任一子条件满足即可（或） |
| `none_of` | 列表：任一子条件满足即否决（非／排除） |

顶点种类按场景库的顶点标签判定。同一个内容字符串既是进程又是文件时（例如 `/usr/bin/shred` 既是进程内容、也有同路径的文件顶点），`vertex` 条件按「该内容可能的种类里有一个相符即算满足」；取不到种类（连不上库）时**不判定种类**，只按内容匹配，并在输出里提示。

## 二、取边标准

### 2.1 范围

- **锚点**取攻击的最终产物（一个顶点 + 一次事件）；**入口**取受害机日志里最早的可归属动作。
- 只收入口到锚点之间的动作；事件号大于锚点的全部不收；锚点后重复出现的、锚点前已收过的同一条边不再收。
- 按内容去重后，每条边必须在锚点前至少有一个实例。

### 2.2 归属判定（满足任一项即可收）

- **网络端点**：攻击方地址参与建立的连接。
- **文件**：攻击创建、改动或删除的（投递物、脚本、产物、被写入的配置、被删对象）。
- **进程**：攻击投递或攻击调用的（会话解释器、脚本、下载／改权限／删除／覆写等工具）。
- 三者都不含 → 机制边，默认不收（例外见 2.4）。

### 2.3 取边四条件（全满足才收）

1. 图上真实存在（按内容口径能找到同内容的边）；
2. 能归属（见 2.2）；
3. 是攻击动作或它的直接后果，不是常态机制；
4. 三元组去重（同一内容只列一条，见 1.2）。

### 2.4 删重复

判据一句话：**删掉它，攻击链的哪个结论会站不住？** 答不出就删。

---

## 三、写规则的三条硬约束

发布前必须在窗口的图上逐条验证；任一条不成立，标准答案不合格。

1. **纯度**：满足任一规则的边都必须是攻击路径上的边；窗口内正常活动的边不得满足任何规则。
2. **互斥**：窗口内任意一条边最多满足一条规则。
3. **两不相交**：规则不得覆盖任何必须条目的三元组——不允许存在「既是必须条目、又是规则命中」的边。

---

## 四、连通性

- 目标：必须条目 + 规则覆盖边构成**一个连通分量**。
- 不通时补最少的桥边（连通两片只需一条），语义优先级从高到低：攻击者启动工具／脚本被执行／关键文件被读取／纯机制边。
- 图上不存在的因果（调度任务、脚本互相调用、认证读取文件）不补，靠时间与说明文字读。

---

## 五、发布前校验

1. 每条边在图上找得到，0 缺失；
2. 无重复三元组，动作编号与边编号连续；
3. 每条边在锚点前有实例；
4. 规则覆盖数与实测一致，三条硬约束（见「三」）通过；
5. 含规则覆盖边后连通分量 = 1；
6. 计数自洽。

---

## 六、命中判定

### 6.1 报告边预处理

- **去重**：内容相同的三元组只保留一条。
- **合法性**：报告边必须能在窗口的图里找到同内容的那条边；找不到的不参与任何命中判定，但**仍计入查准的分母**。

### 6.2 必须条目命中

报告里存在与该条目源、系统调用、目标三部分全等的边，该条目即命中。

### 6.3 规则命中

报告里存在至少一条边满足该规则的全部条件（`source`／`action`／`target`，按 `direction` 绑方向；如填了 `edge` 还要满足其数值条件），该规则即命中。

- 多条边命中同一条规则：该规则只算命中一次。
- 一条报告边同时命中一个必须条目和一条规则：不可能出现（两不相交）。

### 6.4 计数

- 命中步骤数 = 命中的必须条目数 + 命中的规则数。
- 一个步骤最多产出一分。

---

## 七、召回与查准

- **召回**（按步骤）：分子是命中的步骤数，分母是标准答案的步骤总数（必须条目数 + 规则数）。
- **查准**（按边）：分子是报告里去重后属于标准答案的边数，等于「报告里命中必须条目的边数」加上「报告里满足某条规则的边数」（两部分不重叠）；分母是报告按内容三元组去重后的总数。

补充口径：

- 顶点内容取法沿用既有口径：进程取可执行文件路径（没有则取名字），文件取路径，网络端点取本机地址端口指向远端地址端口。
- 满足某条规则的边**全部**算正确，不设按规则的上限。
